# Time Tracking

Time in inundated is recorded as **time entries** on the Timesheet, and
organized using **tags** and **projects**.

## Time entries

A time entry (internally a "timespan") is a manual record with:

- a **name**,
- a **start** and **end** time, and
- zero or more **tags**.

The Timesheet view lists entries newest-first, grouped by day, and lets you
add a new one from a form at the top — pick tags, set a name and time range,
and submit. There's no running/live timer: entries are logged with an
explicit start and end (typically added right after finishing a stretch of
work, or backfilled).

## Tags

Tags are the actual unit time gets attributed to. Each tag has a name and a
color, and accumulates a total duration from every time entry that carries
it. A single time entry can carry multiple tags, so time can count toward
more than one thing at once (e.g. a client tag and a work-type tag).

## Projects

A project is a named, colored grouping of tags, with an optional **time
budget**. A project's total time is the sum of the duration of every time
entry carrying any of its tags — a project doesn't own time entries
directly, it's a lens over the tags assigned to it. This lets you reorganize
which tags roll up into which project without touching any historical time
entries.

Every project also owns a **project tag**, named after the project and
drawn as an outlined pill starting with `@`. A time entry or task carrying
it counts toward the project directly, with no shared tag needed:

- Type `@` in a tag field to see only projects.
- Type `@` and a new name, then press Enter, to create a project on the
  spot, colored from its name.

A project tag takes its project's name, color and archived state, and goes
away with the project. Project tags aren't listed on the Tags page, and a
project can't carry another project's tag.

Projects and tags can each be archived independently, which hides them from
pickers without deleting their history.

Time logged on a [task](/docs/features/tasks) also counts toward the task's
tags and projects.

## Display settings

Per-scope settings (under **Settings** in the app) control how times and
dates are rendered — they don't affect what's stored:

| Setting | Options |
|---|---|
| Week start day | Monday, Sunday |
| Timezone | Any IANA zone, or "browser" (use the client's local zone) |
| Duration format | Long (`1h 30m`), decimal (`1.5h`), clock (`1:30`) |
| Time format | 12h, 24h |
| Date format | ISO, US, EU, or text |

All times are stored and computed in UTC on the backend; these settings only
change presentation.
